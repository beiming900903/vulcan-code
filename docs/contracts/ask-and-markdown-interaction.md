# Ask 与 Markdown 交互约定

本文仅在修改 `ask` 工具、提问运行时、Ask WebUI、只读 Markdown 预览或会话 Markdown 渲染时阅读。

当前源码权威入口：

- [`question_runtime.rs`](../../crates/vulcan-agent-runtime/src/agent_runtime/question_runtime.rs)；
- [`tooling/bridge.rs`](../../crates/vulcan-agent-runtime/src/tooling/bridge.rs)；
- [`ask-question-dialog.tsx`](../../apps/vulcan-code-web/src/components/ask/ask-question-dialog.tsx)；
- [`conversation-markdown.tsx`](../../apps/vulcan-code-web/src/components/conversation/conversation-markdown.tsx)；
- [`prose.css`](../../apps/vulcan-code-web/src/ui-kit/styles/prose.css)。

## 一、Ask 工具边界

- 新的已完成 Ask 结果共用一份回答 Markdown，宿主仅保存 `ask.payload.format = markdown`。
  题目仍取原调用参数，待回答和结算事实仍由 QuestionRuntime 持有；不通过解析 Markdown 恢复选择状态。
  旧的结构化答案按历史契约读取。具体输出边界见 [会话工具结果契约](tool-result-presentation.md)。

- 模型可见工具只注册 `ask`，不保留 `question` 别名。
- `ask` 的 description、Schema 和参数说明使用英文。
- 工具最终模型输出使用 Markdown。
- 运行时必须复用共享 `QuestionRuntime`；刷新 Runtime Foundation 或启动流式请求时不能重建并丢失
  等待中的问题。
- 关闭或放弃 Ask 必须先进入明确的拒绝确认，再中断工具调用和后续对话执行。
- 回答与拒绝的会话 hook（`record_question_answered`/`record_question_rejected`）通过
  `QuestionRuntime::reply_then`/`reject_then` 在可靠提交之后、被阻塞的工具恢复之前记录，且在 pending 锁之外
  运行；拒绝会结束本次运行，事后记录可能落在提问回合关闭之后而新建空回合。权限审批请求不进入提问 hook。

## 二、当前键盘状态机

- `Esc`：答题阶段进入放弃确认；确认阶段返回答题。
- `Enter`：答题阶段校验当前题并前进；提交确认阶段提交；放弃确认阶段确认放弃。
- `Shift+Enter`：在文本输入中保留换行，不触发前进。
- 输入法组合输入中的确认键不触发前进或提交。
- `←/→`：答题阶段切换题目。
- `↑/↓`：非文本输入焦点下移动选项。
- `Space`：答题阶段切换当前单选或多选项。

键盘行为必须以当前 `ask-question-dialog.tsx` 状态机为准。修改后同步更新本节，不能继续引用早期
“Space 在确认页提交”等已经失效的交互。

## 三、文本题、选项题与确认

- 纯文本题进入后直接显示并聚焦输入框。
- 带选项题可以保留“其他回答”，只有选中后才展开自定义输入。
- 提交前必须校验全部必答题；存在未完成项时回到精确题目和错误位置。
- 提交确认与放弃确认是两个明确状态，不能用关闭按钮绕过。
- Ask 面板必须限制在当前会话区域，不能覆盖或劫持其他窗口的键盘输入。
- 面板是会话内非模态对话框，不向辅助技术声明全局模态。选项获得实际键盘焦点后，同步其高亮项；文本题和其他回答保留可访问名称。
- 提交和终止以请求标识隔离，同步防重；失败保留草稿及明确错误并允许重试，成功确认后等待权威待处理请求移除。旧请求回包不得修改新请求。

## 三之一、工具调用审批

权限闸门升级的工具调用经 [`question_runtime/approval.rs`](../../crates/vulcan-agent-runtime/src/agent_runtime/question_runtime/approval.rs)
复用同一 `QuestionRuntime` 与 Ask 面板，待处理请求带 `approval` 权限事实（工具、权限模式、命令或路径、
高风险类别键、规范允许/拒绝标签）。

- 回复只接受快照携带的 `allowLabel` 或 `denyLabel`；回复使工具恢复执行或返回拒绝，不完成工具，也不中断会话。
- 放弃（拒绝请求）取消该调用并中断会话，与 Ask 相同，必须先进入停止确认。
- 客户端按自身语言渲染权限事实，问题文本只是英文后备；未知高风险键按原样显示。
- 设有审批等待上限时快照带 `deadlineUnixMs`，客户端显示剩余秒数（最后 10 秒醒目）。截止时间由服务掌握：到期由
  服务经持久回复路径写入拒绝，先到的用户回答优先；客户端归零后不自行回复，只等待请求离开。等待秒数的设置见
  [`permission-modes-and-judge.md`](permission-modes-and-judge.md)。
- `Enter` 从不批准。WebUI 只经按钮允许或拒绝，`Esc` 进入停止确认，确认阶段 `Enter` 停止；
  TUI 用 `a` 允许、`d` 拒绝、`x` 进入停止确认，`Esc` 把焦点交回输入框。
- 实现入口：[`tool-approval-bar.tsx`](../../apps/vulcan-code-web/src/components/ask/tool-approval-bar.tsx)、
  [`ui/ask.rs`](../../apps/vulcan-code-tui/src/ui/ask.rs)。

## 四、Markdown

- 主会话和子会话转录共用各自的按帧事件窗口。已建立的普通助手 Markdown 回复追加正文时，按会话、窗口代次、服务代次及事件序号更新正文组件，复用转录结构。新增、封口、重连替换或转为专用转录块时沿原投影更新，正文仍以同一事件窗口为准。

项目首页可登记本机附属文件夹。会话内打开文件时，绝对路径按目录边界归属主目录或已登记的附属目录，重叠时优先最具体的根目录。
命中附属目录的文件进入右侧文件面板并按原有规则定位行号。相对路径从会话项目主目录解析，目录外文件继续使用会话的工作区外文件策略。

- 网页快捷链接使用普通 Markdown：`[打开网页](https://host/path)`、`[打开本地网页](file:///C:/path/page.html)`；路径空格应百分号编码。`file://` 只放行超链接，不放宽脚本、嵌入内容或图片 URL 策略。
- 正文中的裸网址与文件引用由 [`conversation-link-literals.ts`](../../apps/vulcan-code-web/src/components/conversation/conversation-link-literals.ts) 在 remark-gfm 之后统一识别（GFM 由裸网址生成的链接先还原为文本，因为它会吞入中文与全角标点；手写链接、`<url>`、电子邮件、代码段与围栏代码不处理）。规则：
  - 网址以 `http://`、`https://` 或 `www.` 开头，前一字符不是 ASCII 字母或数字；只含 RFC 3986 URL 字符，遇空白、中日韩文字、全角标点或 `<>"{}|\^` 与反引号即结束；末尾 `.,;:!?'*` 与不配对的 `)`、`]` 修剪。主机须为 localhost、IP、带端口名称或以至少两字母顶级域结尾的点分名称，因此流式输出中的半截地址保持为文本。含中文路径的网址在首个中文字符前截断，需完整链接时用 Markdown 链接或 `<...>`。`www.` 补全为 `https://`。
  - 文件引用为 `file://` URL 或绝对路径（盘符路径，或至少含一层文件夹的 `/` 根路径），必须以字母开头的扩展名结尾，可带 `:行` 或 `:起-止`；名称可含中文，不跨空白、全角标点与 `#`。相对路径不自动链接（行内代码路径仍按原规则可点击）。绝对路径转为 `file:///` 链接后与手写文件链接同样路由，存在性在点击时检查。
- 只读文件查看（阅读，不提供编辑）：PDF、Word（`.docx`/`.doc`）、电子表格（`.xlsx`/`.xlsm`/`.xlsb`/`.xls`/`.ods`）与 PowerPoint（`.ppt`/`.pptx`）归为服务的 `document` 文件类别，在文件面板中由对应查看器显示，不受图片/视频显示授权门控。会话文件引用由 `workspace-file-open-request.ts` 的 `routeWorkspaceFileOpen` 判定：归属主目录的查看器文件在文件窗口中打开，其他主目录文件与附属目录文件进入文件面板，已登记根目录之外（或没有项目时）的文件先经“工作区外文件访问”检查。
- 工作区外文件访问：系统设置 `outsideWorkspaceFileAccess`（`deny` 禁止 / `prompt` 提示 / `allow` 允许，缺省为提示，只在内存中补默认值，只有用户在设置页选择时写入配置）是总默认；会话可在会话设置中另选，自有选择存于会话目录旁置文件 `outside-file-access.json`（`{ version: 1, access }`，未知字段、取值或其他版本即报错），文件缺失表示跟随系统。生效值为会话选择，否则系统默认，由 `service_session_outside_file_access` 返回。项目外文件经文件操作宿主的 `outside` 操作：禁止时只提示不打开；查看器文件与服务按名称归为 `code` 的文件（`workspace.files.kind`，不读文件）允许时直接在文件窗口中打开，提示时询问“打开 / 在文件夹中显示 / 用默认程序打开（仍经可运行文件校验）/ 取消”，勾选“本会话不再提示”即把会话选择保存为 `allow`；其他文件及没有会话的请求转入下述“不能在侧边栏显示的文件”。项目外文本在窗口或查看页签中只读显示，经 `workspace.files.readOutside`（绝对路径，与文件面板相同的 1 MiB 有界预览）读取。已打开的文件在窗口与查看页签之间移动（`window` / `dock`）不再检查。该提示只防误开，不是安全边界。
- 文件窗口：每个文件一个可移动、可缩放、可最大化的浮动窗口，复用 `ProjectFloatingLayer`；同一文件再次打开时还原并置前已有窗口，新窗口按槽位层叠错开。所选会话在输入区上方显示文件任务栏（仅有窗口时出现），每个条目是其窗口的最小化目标（精灵动画），最小化后条目变暗保留，点击还原并置前，条目上的关闭按钮关闭窗口。切换会话时只显示该会话的窗口与任务栏。标题栏提供全屏阅读（浏览器 Fullscreen API，Esc 退出）、挂到右侧、最大化、最小化与关闭；挂到右侧关闭窗口并在右侧唯一的“查看”页签显示该文件（以文件名命名，每次替换为新文件），页签路径行的“在窗口中打开”再关闭页签并回到窗口。各会话的窗口列表与最小化状态是本浏览器的界面布局，只存于 `localStorage` 的 `vulcan.file-windows`（窗口几何按槽位存于浮动层自身的键），不进入会话数据，格式错误的记录直接丢弃。实现见 [`file-windows/`](../../apps/vulcan-code-web/src/components/file-windows/)，窗口层、任务栏与存储均延迟加载。查看器扩展名表唯一实现为 [`file-viewer-kind.ts`](../../apps/vulcan-code-web/src/components/file-viewers/file-viewer-kind.ts)，须与服务端 `path_metadata.rs` 的 `document` 类别保持一致。
  - PDF 与 Word 经本地媒体路由 `/asset` 获取，分别由延迟加载的 pdf.js（`pdfjs-dist`，字体、CMap、wasm 与 ICC 数据由 Vite 插件复制到 `pdfjs/`）与 `docx-preview`（不渲染 altChunk）显示；文档内网页链接以新窗口打开。
  - 电子表格由服务 RPC `workspace.files.sheet` 用 calamine 读取，只返回单元格显示文本；行、列、单元格长度与文件大小上限只在 `sheet_preview.rs` 定义，超出时界面显示截断提示。
  - Word 97–2003（`.doc`）与 PowerPoint（`.ppt`/`.pptx`）同属 `document` 类别，由服务 RPC `workspace.files.officePdf` 调用服务宿主自身安装的 LibreOffice（标准安装位置，其次 `PATH`；不随包分发、不自动下载）无界面转换为 PDF，再由同一 PDF 查看器显示。转换使用缓存目录内的独立用户配置，同一时间只转换一个文件；超时即终止整个进程树，请求取消时同样终止。缓存位于系统临时目录 `vulcan-code-office-pdf/`，按路径、大小与修改时间命名，超过保留期的缓存与遗留工作目录在下次转换时清理；扩展名、超时与保留期只在 `office_pdf.rs` 定义。未安装 LibreOffice 时返回 `converterMissing`，界面说明需要安装 LibreOffice，桌面端另提供“用默认程序打开”（仍经可运行文件校验）；不探测其他转换器。
- 不能在侧边栏显示的文件（文件面板归为 `other` 类别的项目文件，以及既无查看器也不是文本的项目外文件）点击后不再静默失败：桌面端经 `workspace-file-actions.tsx` 的延迟加载对话框询问“是否用系统默认程序打开”，提供打开、在文件夹中显示与取消；网页端只提示无法预览并提供复制路径，不提供任何系统操作。文件面板中这类文件的“暂不支持预览”页直接给出同样的操作（`workspace-file-os-actions.tsx`：桌面端“用默认程序打开 / 在文件夹中显示”，网页端“复制路径”），桌面端文件树右键菜单与文件栏“更多”菜单另有“用默认程序打开”，经同一对话框宿主。
  - 程序与脚本（可执行文件、安装包、快捷方式、脚本宿主与解释型脚本，以及非 Windows 平台带执行位的文件）永不由会话链接用默认程序打开，对话框只提供在文件夹中显示。可运行扩展名表唯一定义在桌面主进程 [`local-file-actions.ts`](../../apps/vulcan-code-desktop/src/gui/local-file-actions.ts)，界面只通过 `localFile.inspect` 得知能否打开；主进程在打开前再次校验绝对路径、文件存在且不可运行，不信任界面判断。
  - 桌面端 Ctrl 点击（macOS 为 Cmd 点击）文件引用直接用默认程序打开，可运行文件仍只给出在文件夹中显示；会话右键菜单对文件引用提供“打开 / 用默认程序打开 / 在文件夹中显示 / 复制路径”，网页端只保留第一项与复制路径。三个本地文件 IPC 通道只接受工作台主框架调用。
- Markdown 链接前显示装饰性地球图标并持续显示下划线，长链接保留正常换行；文件链接使用点状下划线以区别于网页链接。桌面会话右键菜单提供“复制链接地址”，使用实际链接 URL 而非显示文字，支持点击图标及文字；空链接与普通正文不显示该操作。网页端继续使用浏览器原生链接右键菜单。
- 桌面端复用“基础设置 → 用内置浏览器打开链接”：开启时在当前会话的右侧浏览器打开 HTTP(S) 与本地网页，关闭时交给本机默认 URL 处理程序（HTTP(S) 通常是默认浏览器，文件按系统关联）。设置默认开启，不自动回写。网页端隐藏该设置，保留新标签链接；HTTP(S) 页面能否打开 `file://` 由浏览器安全策略决定，不能承诺绕过本地文件访问限制。
- 关闭会话内置浏览器使用共享应用内确认框，页面数来自归属匹配的原生快照；确认后通过受限 IPC 传递明确布尔决策。原生端按会话销毁全部页面并等待资源释放后，界面才移除页签。确认框期间隐藏原生网页视图，取消恢复；失败保留弹窗，切换会话不得让迟到回包移除其他会话的页签。
- 链接点击只接管当前会话正文的普通主键点击；保留下载、资源预览、工作台同源链接和修饰键行为。桌面外部打开经受限主框架 IPC 校验，禁止脚本协议及工作台来源。AI 能力声明位于不可编辑的产品功能说明 `system-prompts/capability-guide.md`，在 Provider 请求头部的固定开发者层发送。
- 会话 Markdown 复用当前 `conversation-markdown` 渲染链路，不建立第二套解析器。
- 动态思考弹窗默认显示可选择、可复制并保留换行的纯文本；标题栏右侧的 `MD` 按钮切换
  Markdown 渲染，开启时高亮。选择按客户端保存在 `localStorage`，跨会话和重启保留；
  未保存时使用默认关闭状态，不自动回写。仅开启后挂载既有 Markdown 渲染器，不影响左侧按钮的手动思考预览。
- 上下文压缩运行时在当前会话的居中浮层显示思考和流式摘要，复用思考浮层的独立滚动视口。
  会话转录只显示状态行，实时正文不计入转录高度。压缩结束后关闭浮层，原位置保留默认收起的摘要或失败详情。
- 回答组件是信息串为 `ui-<name>` 的已闭合围栏，由同一 `conversation-markdown` 链路原生渲染，不执行脚本、不建立第二套解析器；语法与模式语义见 [回答模式与回答组件](answer-mode-and-components.md)。
- 行内公式写作 `` $`…`$ ``（GitHub 写法），在任何回答模式下都由同一链路清理之后的 rehype 步骤识别并以延迟加载的 KaTeX 排版；普通 `$…$` 不识别为公式。
- 工作台内，形如带目录分隔符与扩展名路径的行内代码（可带 `:行` 或 `:起-止`，例如 `` `src/app.ts:12-20` ``）渲染为
  可点击且可键盘激活的 `code` 元素，在右侧文件面板打开该文件并定位、着色对应行；仍按文本选择与复制。裸文件名、
  成员访问、URL、通配符与围栏代码不处理；工作台之外（无文件面板）保持普通行内代码。识别规则唯一实现为
  `workspace-file-open-request.ts` 的 `parseFilePathMention`，工具卡与审核面板的“在文件面板中显示”共用同一开文件通道。
- 需要“可选择、可复制、只读”的预览时，使用可选择文本或只读编辑区，不退回不可复制的普通展示。
- 仅显示 Markdown 外观但用户实际需要复制内容时，也必须保留文本选择能力。
- Markdown 样式修改应作用于精确范围，不能污染代码块、工具卡片或其他非会话区域。
- Mermaid 在消息完成后渲染；保持严格安全模式与 SVG 图片隔离。渲染结果必须经过 XML 序列化，
  不能把包含 HTML 空元素（例如 `<br>`）的标记直接作为独立 SVG 图片加载。
- Mermaid 解析或图片加载失败时，保留可复制的源码并显示可展开的失败原因，不能静默退回普通代码块。
- Mermaid 支持点击图表或标题栏按钮展开，复用图片查看器的缩放、拖动、自适应、最大化和关闭操作。
  查看器直接使用当前 SVG Blob，不重新调用模型；关闭弹窗不释放仍由会话缩略图使用的 Blob。
- Mermaid 卡片提供“图形 / 源码”切换；源码以可选择的原始文本显示，两种模式均可复制源码。
  切换仅影响显示，不重新生成图表或释放其 Blob，切回图形后仍可展开查看。

## 五、代理协作展示边界

- 代理之间的问题、阶段通知和子任务结果不进入人类 Ask 弹窗，不继承人类拒答会中断任务的语义。
- ChatArea 分支时间线与事件原生时间线共用 `conversation-collaboration-card.tsx`。卡片身份来自强类型 V1 事件，不把代理消息改成人类提示词。收到的问题正文目前只存在于宿主 `agent_message` 输入的 XML 信封中；展示解码必须同时校验输入来源、`agent-message:{event_id}` 动作身份、接收会话、版本和问题类型，不能识别人类或助手正文中的同名标签。
- 上述 XML 展示解码的契约归属是 `crates/vulcan-ai-contract/src/host_message.rs` 的 `HostMessageEnvelope::render` 和 `HOST_MESSAGE_ENVELOPE_VERSION`。修改宿主信封时必须同步 `conversation-agent-question-input.ts` 及其夹具测试；不新增正文持久化副本。其他代理输入镜像继续隐藏，答案以 `question_answered` 的强类型答案快照展示，避免重复。
- 子任务最终结果使用独立卡片和既有 Markdown 渲染链路，不合成为主会话最终回复。阶段通知没有回答义务或问题撤销控件。
- 发出的代理提问和子任务完成结果使用默认收起的工具卡：讨论图标、事件标题、状态及智能体名字。名字从持久化工具结果解析，并以当前宿主导航中的名字为准。子任务成功结果标题为“智能体工作完成”；展开后显示正文，复用工具卡折叠记忆与视口测量。
- 提问方已有 `question_created` 卡时，成功 `ask_question`／`ask_parent` 的 `collaboration_receipt_v1.payload.question_id` 与该卡精确匹配后，隐藏重复工具回执，只保留带目标会话名的问题卡。失败、活动中、身份未匹配或分页尚未加载问题卡时保留工具显示；不按名称、正文或时间相邻关系合并，不删除持久工具事实或统计。
- 提问卡只显示问题正文，回复卡只显示答案正文，不能用最新问题快照把答案追加到原提问或把原问题重复到回复。收到的提问和答案复用接收消息气泡；发送的问题保留工具卡。`answer_delivery` 按精确 `question_id` 和独立 `delivery_revision` 更新回复状态，不独立成卡、不改变原回复时间和位置；仅含回执的分页不生成空回复。
- 接收问题的执行方不单独显示“问题执行”卡。`question_execution` 的开始、完成和失败状态按精确 `question_id` 合并到收到的提问气泡，正文和接收时间不变；已结算的回答或撤销状态不得继续显示旧“运行中”。只包含执行记录、未加载问题正文的分页不生成空卡，也不从其他问题借正文。
- 协作投递不独立成卡，按精确问题身份附加到原提问、回复或等待工具卡；子任务状态按执行身份附加到创建卡。不得用名称或事件相邻关系推断归属。
- 同一任务消息按不可变投递身份合并为一张卡；后续接纳和应用回执更新其状态，不能按正文或名称去重。排队任务在目标认领后按精确效果绑定新回合，卡片展示位置移到认领处，避免夹在上一回合中；原始序号和接收时间保留。任务最终结果仍独立展示。
- 同一通知按 `notification_id` 合并为一张卡，已记录、已接纳、已投影等后续快照只更新首张卡的状态。发送方的 `send_session_message`／`send_notification` 工具回执在 `collaboration_receipt_v1.payload` 中保留 `delivery_id`／`notification_id`；回执与发出的任务消息或通知精确匹配时，状态显示在该工具卡上，不再生成重复的发出卡。收到的消息、通知与任务结果保留各自的卡片；缺少这些身份的旧回执保持原有显示。
- 任务结果的送达确认与上下文写入回执不独立成卡，按原任务投递身份附加到结果卡，显示“已送达”或“已加入上下文”。任务结局与正文保持独立；迟到确认不得回退上下文写入进度。窗口只含回执时不生成空卡，历史事件仍完整保留。执行会话中已完成且未撤权的任务结果不显示结果卡（最终回答已在其正上方）；停止、放弃或撤权的结果保留卡片，展开说明原因。标题之外无内容的协作卡不可展开；过长的会话名称在标题行内以省略号截断。
- 所有协作消息卡均不显示技术详情或原始协议快照。收到的会话任务、阶段通知、任务结果、提问和答案右对齐，复用用户气泡外观但保留协作角色；气泡上沿显示消息类型、来源会话名和状态。短正文默认完整可见，无整卡折叠；长正文按与用户提示词共用的行数限制收起超出部分，使用浅色下箭头展开和收起。时间位于气泡外侧右下方，不提供复制或编辑按钮。发出的消息和结果保留工具卡布局，只显示目标会话名。子代理完成结果保留工具卡。
- 会话名称放在标题行且可按宿主路由跳转；名称使用方括号包裹，左括号右侧放跳转图标，括号前后无额外间距，悬停仅链接显示下划线。不显示当前会话自身或重复的“来源／目标”标签，页脚只保留时间。工具卡标题整行可点击折叠，跳转链接是独立的同级按钮，点击名称不得改变展开状态。收到的气泡仍仅折叠超长正文。名字来自宿主会话标题或智能体标签；未知名称不显示空按钮或内部身份。
- 代理问题不提供界面撤销入口，是否撤销由智能体通过工具决定。卡片导航只使用宿主给出的精确会话路由。
- 持久事件保留原始快照；展示层使用窗口中的最新权威问题状态更新原卡片，已完成的问题不继续显示等待处理。所有状态汇总仅用于展示，不修改执行状态。
- 独立会话发送消息显示“向[会话名]会话发送消息”，接收消息显示“收到来自[会话名]的消息”，发出结果显示“回复[会话名]结果”。未知名称保留通用消息类型；子代理完成卡保持独立语义。运行中插队归当前回合；显式排队保持排队语义，在认领执行时开启新回合。空闲收到任务不伪造人类提示词。
- 新回合的收到任务气泡位于“正在工作／已工作”分隔线上方，不参与工作过程的整体折叠；回合内插队消息仍位于过程内部。
- 没有人类提示词的回合仍按规范回合标识组织过程、思考和工具组。任务结果按其终态回合标识显示在对应统计行之前；不得按最近一条统计、时间邻近或会话名称猜测归属。分页窗口缺少该统计时，结果保留原展示位置。

## 六、代理任务与用户记忆边界

- 人类提示词排队保持用户输入语义。代理之间的显式排队和插队不进入人类输入观察；不能因为模型协议使用带标签的 `user` 消息就按人类输入处理。
- `AgentTask` 仍具有完整执行回合、内部业务钩子归属、结束清理和统计，但禁止自动用户观察、画像准备、完成回写及停止通知；也不注册或消费用户记忆回合的临时记忆寿命。
- `BusinessHookBinding.observes_user` 随原始业务归属持久化，恢复和续跑继承该值；捕获、恢复和冷加载均校验它与当前回合来源一致。不得仅依据续跑时的提示来源重新推断用户身份。
- 真实用户在代理工作期间排队输入或回答问题，仍走真实用户通知路径；禁止在公共通知出口按当前回合来源全局封锁。
- 运行中收到代理插队保持原回合。它不注册用户输入观察，也不改变原回合的用户记忆策略；由原用户发起的回合仍正常完成其记忆流程。
- 本轮修改不自动触发记忆工具，也不禁用智能体显式调用记忆工具的能力。完整来源约束以回合准入、业务钩子捕获和定向测试为准。

### 统一等待与迟到结果

- 代理通信统一通过 `wait_agents_result` 接收问题、答案、阶段通知及最终结果。返回部分消息时仍需检查 `remaining_work`；`pending_work_count` 只包含已确认运行的工作，无法确认的计入 `unverified_work_count`。
- 已确认的异常报告按工作、结果和原因去重，但每次等待仍重新检查未结工作的真实所有者；对方恢复后，同一个问题重新可等待。历史开放回合本身不能证明仍在运行。
- 目标读取失败返回 `check_failed` 和逐目标错误，不伪造中断、不清除工作，也不隐藏其他参与者已到达的消息。只有明确存储缺失和实际执行丢失才能报告不可用。
- 当前回合已有未回答问题时，等待返回 `needs_reply`；智能体使用 `reply_question` 回答或说明无法回答，再继续等待，避免双方循环阻塞。这不增加最终结束的强制回复门槛。
- 明确任务和问题沿现有准入唤醒空闲执行；阶段通知和迟到答案、结果只可靠保存，等待下次执行投影，不单独唤醒。停止策略及直属子代理对 MainOnly 的例外保持原有权威。
- 每次请求边界优先投影问题、答案、任务方向和最终结果；阶段通知按原接纳顺序分批，超额部分保持未投影。条数与总字节上限只在 `agent_collaboration/projection.rs` 定义，正文预算复用宿主信封上限。
- 跨回合的答案和任务结果前附 `result_context`，包含原回合、接收回合及有界原请求摘要。引用是旧请求语境，不是新任务；完整结果正文及分块凭据不被改写。引用与结果原子追加，重放不重复。撤权结果不披露原请求摘要。结果卡不重复原任务（其发送工具卡或收到的消息卡位于同一会话），问题卡保留原问题及回答，不增加技术详情。

## 七、修改后的最低验证

工具卡及工具组的手动展开、收起和自动折叠均属于布局变化，不能主动解除已有锁底。锁底时在动画中间测量和结束后继续跟随底部；未锁底时保持既有阅读锚点。真实用户滚动及显式跳转仍可转移滚动所有权，并使旧布局恢复事务失效。主会话与子任务按精确界面标识隔离。

- `ask` 是唯一模型可见提问工具；
- 共享 `QuestionRuntime` 在刷新和流式启动后仍保留等待请求；
- 键盘、文本题、单选、多选、其他回答、提交确认和放弃确认均有测试；
- Markdown 可选择、可复制且经过当前会话渲染链路；
- overlay、焦点和快捷键不影响会话之外的控件。
