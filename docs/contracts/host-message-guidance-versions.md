# 宿主消息指引版本与升级

## 权威与触发条件

本契约归属于 `vulcan-ai-contract/src/host_message/guidance.rs` 与服务内核 `provider_v1_sink/host_guidance.rs`。修改固定指引、版本识别、请求同步或锁定基线校验时，必须同步本文与对应回归。

固定指引解释协作消息、问题回答、任务终态和上下文标签。其正文会随初次请求保存在会话锁定基线中，程序升级不能把旧正文与最新常量逐字比较后直接拒绝。

## 版本规则

1. `HOST_MESSAGE_GUIDANCE_REVISIONS` 是唯一、只能追加的正文目录。新语义必须新增末尾条目，不能修改、删除或调整既有条目的顺序。
2. `HOST_MESSAGE_GUIDANCE_VERSION` 与当前正文均从目录派生，不能另设独立版本常量。
3. 历史文本必须有源代码事实，精确匹配字节；不去除空白，不依据前缀、关键词或来源名称宽松放行。
4. 正文版本、宿主信封版本和元数据结构版本分别管理。本次正文升级不改变持久字段，不递增元数据结构版本。

## 请求行为

- 新建或正常刷新后的基线使用最新固定指引。
- 物理请求先发送本次执行解析的基础系统提示词与固定代理指令，再发送锁定系统指引、固定开发者指令与锁定开发者指令，最后接项目上下文和有时序的历史。项目或用户编辑基础提示词后，下次执行读取生效覆盖，无需刷新会话代际。
- 已初始化基线以持久化运行时为权威，候选请求不能替换它。已登记的旧指引保留原始正文和身份字段。
- 来源必须继续满足既有节点名、种类、目标角色、标签和来源标识约束；未知正文或错误身份明确失败。
- 每次普通业务请求同步完整动态上下文时，加入唯一生产者 `dynamic.host_message_guidance`。旧基线对应最新全文升级；当前基线对应撤下已过时的升级覆盖层。
- 升级复用持久 `SystemContext` 事件，投影为当前位置的带标签 `User` 消息。不会创建用户输入、用户回合或用户记忆钩子。
- 相同版本通过既有原文指纹与生产者状态保持幂等，重试和冷加载不重复追加；后续再次升级追加新版本，保留先前历史。
- 压缩请求不拥有业务生产者，不撤下或覆盖升级消息。压缩生成的新窗口通过既有有效上下文回填保留当前说明。正常基线刷新后，冗余升级通过失效标记退出，不能重写旧历史。

## 验证入口与边界

```powershell
rtk cargo test -p vulcan-ai-contract host_guidance
rtk cargo test -p vulcan-service-kernel --lib host_guidance -- --test-threads=1
rtk cargo check -p vulcan-service-kernel --all-targets
```

回归必须覆盖已登记历史文本、非法内容与身份拒绝、物理请求准入、前缀保持、重复同步、文件重载与压缩。真实供应商调用与客户端加载新 Core 属于独立运行验收，纯本地测试不能代替。
